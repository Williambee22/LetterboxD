# Pressboxd Mobile App — exact installation steps

This kit is designed for:

    https://github.com/Williambee22/LetterboxD

It keeps the existing Express/EJS/SQLite/Railway website as the backend and adds a Capacitor v8 native shell for Android and iOS.

## What gets added

After installation your repository will look like:

    LetterboxD/
    ├── app.js
    ├── db.js
    ├── templates/
    │   ├── base.ejs                 <-- automatically patched
    │   └── ...
    ├── static/
    │   ├── mobile-app.css           <-- new
    │   ├── mobile-app.js            <-- new
    │   └── ...
    └── mobile/                       <-- new native app project
        ├── package.json
        ├── capacitor.config.ts
        ├── assets/
        ├── www/
        ├── android/                  <-- generated by Capacitor
        └── ios/                      <-- generated by Capacitor on a Mac

The normal website does NOT show the app bottom navigation. `mobile-app.js` detects Capacitor and enables the native-only UI only inside the installed app.

# PART 1 — put the kit into your repository

## Easiest method

1. Download/unzip this kit.
2. Copy the entire folder `Pressboxd-Mobile-Kit` into the ROOT of your local LetterboxD repository.

You should temporarily have:

    LetterboxD/
    ├── app.js
    ├── db.js
    ├── static/
    ├── templates/
    └── Pressboxd-Mobile-Kit/

3. Open a terminal in `LetterboxD/` — NOT inside the kit folder.
4. Run:

    node Pressboxd-Mobile-Kit/setup-mobile.js

The installer:

- creates `mobile/`
- creates `static/mobile-app.css`
- creates `static/mobile-app.js`
- backs up `templates/base.ejs` as `templates/base.ejs.before-mobile.bak`
- patches `templates/base.ejs`

5. Check the changes:

    git diff

6. Once satisfied, you can delete the temporary `Pressboxd-Mobile-Kit/` folder from the repo. The installed `mobile/` and static files remain.

---

# PART 2 — deploy the website changes first

Commit/push these website changes exactly like your normal Pressboxd updates:

    templates/base.ejs
    static/mobile-app.css
    static/mobile-app.js

Let Railway deploy them.

The desktop website should look essentially the same. The app-specific navigation remains hidden in Safari/Chrome and only activates when `window.Capacitor.isNativePlatform()` is true.

# PART 3 — Android setup (Windows is fine)

Install these first:

- Node.js (your website already targets Node 22)
- Android Studio
- Android SDK from Android Studio
- Java/JDK required by the current Android Studio/Capacitor toolchain

Then, from your repository root:

    cd mobile
    npm install
    npm run add:android
    npm run sync

For a temporary icon, copy your current Pressboxd favicon:

PowerShell:

    Copy-Item ..\static\favicon.png .\assets\logo.png

Then generate Android/iOS icon and splash resources:

    npm run assets
    npm run sync

Open Android Studio:

    npm run open:android

In Android Studio:

1. Let Gradle finish syncing.
2. Choose an emulator or connected Android phone.
3. Click Run.

The app will open `https://www.pressboxd.com` but will detect Capacitor and show the app-only bottom navigation.

## Build a Google Play file

In Android Studio:

    Build > Generate Signed App Bundle or APK

Choose:

    Android App Bundle

Create/select your signing key and build the RELEASE bundle. The Play Store upload file will be a `.aab`.

Do not lose the signing key or its password.

# PART 4 — iPhone/iPad setup

Apple builds require macOS + Xcode.

On the Mac, copy/clone the same repository and then:

    cd mobile
    npm install

If `ios/` has not been created yet:

    npm run add:ios

Then:

    npm run sync
    npm run assets
    npm run open:ios

In Xcode:

1. Select the `App` project.
2. Select the `App` target.
3. Open **Signing & Capabilities**.
4. Pick your Apple Developer Team.
5. Keep the bundle identifier as `com.pressboxd.app`, or change it BEFORE your first App Store release if you want a different permanent identifier.
6. Test on a real iPhone.
7. Use **Product > Archive**.
8. Upload the archive to App Store Connect / TestFlight.

# PART 5 — app icon before release

The included asset instructions support a test icon, but for release make a proper square PNG:

    mobile/assets/logo.png

Recommended source size:

    1024 x 1024 or larger

Then run:

    cd mobile
    npm run assets
    npm run sync

The `@capacitor/assets` tool generates the required platform-specific icon and splash sizes.

# PART 6 — how updates work afterward

## Website/content update

If you change:

- EJS pages
- CSS
- shows
- rankings
- reviews
- forum behavior
- profiles
- server routes
- database-backed content

just deploy Pressboxd to Railway as usual. Because the native shell loads the production Pressboxd origin, the installed app receives those server-side changes without maintaining a second database or React Native frontend.

## Native update

Run a new store build when you change:

- Capacitor plugins
- native permissions
- bundle/application settings
- native icons/splash resources
- Android or iOS project files

After native dependency/config changes:

    cd mobile
    npm run sync

Then rebuild in Android Studio/Xcode.

# Push notifications

Push notifications are intentionally NOT fake-configured here. A working implementation needs:

1. Firebase Cloud Messaging configuration for Android.
2. Apple Push Notification configuration/certificates for iOS.
3. A new database table to store each user's device token.
4. Express API endpoints to register/unregister device tokens.
5. Server-side sends when Pressboxd creates a notification.

The current app shell can be extended with `@capacitor/push-notifications` once those credentials exist.

# Important App Store note

Apple's App Review Guideline 4.2 says an app should provide functionality/content/UI beyond a repackaged website. This kit adds app-specific UI plus native Share, Haptics, Network, Browser and App integrations, but App Review is discretionary. Adding push notifications and/or meaningful offline-native features later would make the iOS case stronger.
